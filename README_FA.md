# ACE CLUB — بسته انتشار

این بسته برای اجرای Node.js روی Render یا سرور شخصی آماده شده است. پوشه `node_modules` و دیتابیس محلی عمداً داخل ZIP انتشار نیستند؛ وابستگی‌ها با `npm install` نصب می‌شوند و دیتابیس باید روی فضای پایدار سرور ساخته یا از پشتیبان خودتان بازیابی شود.

## انتشار روی Render

1. یک Web Service از مخزن GitHub پروژه بساز.
2. Build Command: `npm install`
3. Start Command: `npm start`
4. در Environment این متغیرها را تنظیم کن:
   - `NODE_ENV` = `production`
   - `SESSION_SECRET` = یک مقدار تصادفی و اختصاصی با حداقل ۳۲ کاراکتر
   - `DATABASE_PATH` = `/var/data/dordor.sqlite`
   - `UPLOADS_DIR` = `/var/data/uploads`
5. در بخش Disks یک Persistent Disk بساز و Mount Path را دقیقاً `/var/data` قرار بده.
6. Deploy کن و آدرس HTTPS را باز کن. اولین حساب واقعی که ثبت‌نام کند، سازنده اصلی سایت می‌شود؛ نام کاربری `OWNER` برای ثبت‌نام عمومی رزرو است.

**اگر دیتابیس سایت قبلی را داری:** قبل از Deploy از دیتابیس و پوشه `uploads` نسخه پشتیبان بگیر. بعد از ساخت دیسک، فایل دیتابیس و رسانه‌های قبلی را به مسیرهای بالا منتقل کن یا از ابزار بازیابی داخل پنل مالک استفاده کن. ZIP انتشار دیتابیس نمونه را حمل نمی‌کند و نمی‌تواند داده‌ای را که قبلاً از دست رفته بازیابی کند.

## اجرای محلی یا Termux

```bash
npm install
cp .env.example .env
# مقدار SESSION_SECRET را در .env با یک مقدار تصادفی و اختصاصی عوض کن
bash start.sh
```

سپس `http://127.0.0.1:1074` را باز کن. برای تغییر پورت: `PORT=8080 bash start.sh`.

## امکانات و موارد مهم

- رابط فارسی و راست‌چین، ثبت‌نام/ورود، پروفایل، پیام‌رسانی، درخواست دوستی/پیام، بلاک و رفع بلاک، گروه‌ها، فروشگاه درون‌برنامه‌ای، بازی‌ها، گزارش‌ها و پنل مدیریت.
- بلاک سمت سرور بررسی می‌شود؛ فقط مخفی‌کردن ظاهری کاربر نیست.
- تنظیمات پس‌زمینه در مرورگر همان دستگاه ذخیره می‌شود و بین دستگاه‌ها همگام نیست.
- فایل‌های رسانه در `UPLOADS_DIR` ذخیره می‌شوند؛ برای ماندگاری آن‌ها Persistent Disk لازم است.
- نشست‌ها در حافظه هستند؛ با Restart نشست‌های ورود پاک می‌شوند و کاربر باید دوباره وارد شود. اجرای چند نمونه هم‌زمان پشتیبانی نشده است.
- تماس صوتی به HTTPS و مجوز میکروفون نیاز دارد؛ برخی شبکه‌ها به TURN نیاز دارند.
- خریدهای فروشگاه در این نسخه خرید درون‌برنامه‌ای با سکه/اشتراک‌های داخلی است و به‌تنهایی درگاه پرداخت واقعی یا پیامک OTP واقعی محسوب نمی‌شود.
- پیش از انتشار عمومی، از دیسک پایدار نسخه پشتیبان بگیر و با حساب‌های آزمایشی خودت ثبت‌نام، بلاک، پیام، خریدهای داخلی، پنل مالک و بازیابی پشتیبان را روی آدرس HTTPS بررسی کن.

## نکات امنیتی

- در Production برنامه بدون `SESSION_SECRET` معتبر اجرا نمی‌شود.
- در نصب تازه، اولین ثبت‌نام واقعی مالک اصلی می‌شود؛ حساب فنی مخفی OWNER به‌صورت خودکار ساخته نمی‌شود.
- فایل `.env`، دیتابیس و پوشه `uploads` را در GitHub عمومی قرار نده.
- فایل‌های آپلودی با نام تصادفی و پسوند بر اساس MIME پذیرفته‌شده ذخیره می‌شوند؛ این بررسی جایگزین اسکن کامل محتوای فایل نیست.
- پایگاه داده با `sql.js` در حافظه بارگذاری و پس از تغییر روی دیسک نوشته می‌شود؛ برای ترافیک بالا یا چند نمونه، به دیتابیس سروری و session store پایدار مهاجرت کن.

## سازنده و بازیابی نقش سازنده
در نصب تازه، اولین حساب واقعی ثبت‌نام‌شده سازنده اصلی می‌شود. برای مواقعی که نقش سازنده اشتباهی تغییر کرد، پس از این نسخه از پنل مدیریت یک پشتیبان کامل جدید (`.tar.gz`) بگیرید و امن نگه دارید. صفحه «امنیت و حریم خصوصی» دکمه «بارگزاری فایل» دارد که با همان حساب و همان پشتیبان امضاشده، فقط نقش سازنده را بازیابی می‌کند و دیتابیس سایت را جایگزین نمی‌کند. فایل کلید سرور `.ace-creator-recovery-key` کنار پایگاه داده باید حفظ شود. جزئیات در `UPDATE_2026-10-20_CREATOR-RECOVERY_FA.md` است.

- پشتیبان اکانت (`.json`) اطلاعات پروفایل را نگه می‌دارد و فقط برای همان نام کاربری قابل بازیابی است. این فایل برای بازگرداندن حساب حذف‌شده یا موجودی‌ها طراحی نشده است.
- حالت نگهداری از پنل مالک/سازنده قابل روشن/خاموش‌کردن است و در سطح API هم اعمال می‌شود.

## پست‌های حمایت‌شده و جایزه لایک
- صفحه «پست‌ها» فقط پست‌های حمایت‌شده را در شبکه دو ستونه مربعی و با ترتیب تصادفی نمایش می‌دهد.
- برای ورود به اکسپلور، هزینه پایه ۵۰ سکه پرداخت می‌شود و نمایش به ۵۰ حساب متفاوت محدود است؛ شمارش نمایش با مشاهده واقعی کارت یا بازکردن پست و با ثبت یکتای هر کاربر انجام می‌شود.
- حمایت جایزه‌دار با بودجه‌های ثابت ۵۰، ۱۰۰ یا ۲۰۰ سکه در دسترس است؛ جوایز ۱۰ سکه‌ای هستند و هر کاربر برای هر پست حداکثر یک جایزه می‌گیرد.
- ساخت پست عکس/ویدئو، متن، کنترل نظر و دانلود، گزارش پست و نظر، لینک مستقل `/p/<کد>`، حذف صاحب پست و بررسی مدیریتی گزارش‌ها اضافه شده است.
- هنگام اولین مهاجرت دیتابیس به طرح پست‌ها، سرور به‌صورت خودکار یک نسخه پشتیبان SQLite در پوشه `data/backups` می‌سازد. اگر ساخت بکاپ دیتابیس موجود ناموفق باشد، سرور پیش از مهاجرت متوقف می‌شود.
- جزئیات و محدودیت‌های این قابلیت در `POSTS_RELEASE_FA.md` آمده است.
